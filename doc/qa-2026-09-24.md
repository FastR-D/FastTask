# 2026-09-24 界面复审与打磨

## 范围与方法

- 依据 [`AGENTS.md`](../AGENTS.md) 的产品设计规则复审**已渲染**的界面，只处理浏览器里实际可见的问题，不复述假想的代码质量问题；本轮不新增功能。
- 复审对象是构建产物：`web/dist` 交给本地 FastTask（`FASTTASK_WEB_DIST`）后由 Go 的静态服务路径提供，与生产同一条代码路径，不是 vite dev。
- 采集方式：headless chromium + CDP，逐标签页导出计算样式与几何（盒子、字号、行高、颜色 token、边框、圆角、阴影、内外边距、左边缘），覆盖 1440×950 浅色/深色与 400×860，共 21 个场景；同时导出 PNG 供人工复核。模型本身不读图，所以每条结论都写成可复测的数字。
- 未在生产站点执行任何写操作。

## 实测发现的可见问题

1. 对话页顶部 `.agent-harness-bar` 高 65px、底部一条 840px hairline，条内只有一个 192×56 的填充下拉靠右；探测未回答时状态行为空（等 8s 仍为 `null`），左侧约 640px 全空——一条什么都不分隔的分隔线。
2. 助手 markdown 表格把同一结构编码了三遍：每个 `th/td` 四边 1px 边框 + 表头 `surface-container-high` 填充 + 偶数行 `surface-container-low` 斑马纹；12px 的表格文字被三层底色和网格线包住，读起来像从别的产品粘进来的截图。
3. `.agent-proposal` 是消息内部的第二块填充面，而 mdui 用 `--mdui-color-background` 画 outlined 输入框浮动标签的缺口：拒绝理由标签后面出现一块 `rgb(254,247,255)` 落在 `rgb(247,242,250)` 上的错色补丁；后台 `.admin-form` 同一 token 面板里的「时区」标签同样错色（两处均已实测）。
4. 同一张提案卡里「批准」（filled）与「拒绝」（tonal）都是填充按钮，加上 498×56 的输入框，一行三个同等响度的控件；而 `App.tsx` 里同类决策卡用的是 outlined 拒绝 + filled 确认应用，同一产品两种处理。
5. 会话行固定预留 56px 显示 `toLocaleDateString()` 的英文日期 `9/23/2026`（全站其他日期都是 zh-CN），90px 宽的操作层在触摸端始终不透明地盖在它上面（实测重叠），桌面端悬停时也盖住它；标题因此被压到 115px 并截断。
6. 那些操作图标是 `mdui-icon`，宿主 `width:1em;height:1em`，遇到全局 `*{box-sizing:border-box}` 后 padding 只压缩字形、不放大点击区：实测点击区仍是 18×18。
7. `.admin-card p`（0,1,1）压过 `.eyebrow`（0,1,0），卡片元信息行被抬到 14px/500，与 h3 显示名完全同级；内容是裸枚举 `admin · active`，且 `admin` 在下方 `small` 里又出现一次，违反 `App.tsx` 自己写下的「状态绝不裸显示」约定。
8. 作业行标题旁印完整 36 字符作业 ID（238px），下一行的对象 ID 却已按 18 字符缩写；同一行两种规则，十六进制串比 84px 的标题更抢眼。
9. 400px 下目标横向列表的卡片宽度由各自最长的 nowrap 行决定：实测 538 / 319 / 383px 三种宽度挤在 368px 的滚动区里。
10. 「运行位置」是全站内联工具条里唯一的 filled 字段，而它是极少改动的设置项（mdui 文档把 filled 描述为视觉更强的一档）。

对比度审计只报出 mdui 禁用态按钮，没有真实的对比度不足。

## 本轮改动（以删除为主，+91/−51 行，其中约一半是注释）

- `agent.css`：删掉 harness bar 的 `border-bottom` 与 `padding-block-end`（65→56px）；表格只留行 hairline，删掉单元格竖线、表头填充与斑马纹（连带删掉用户气泡里为表头准备的那条覆盖规则）；`.agent-proposal` 删掉背景填充只留边框；触摸端操作图标回到文档流、给到 34px（`box-sizing:content-box` 才让 padding 真正变成点击区），放不下时整组换行而不是盖住标题。
- `agent/ThreadList.tsx`：删掉会话行日期（被遮挡、语言不一致、还占走标题宽度）。
- `agent/HarnessStatus.tsx`：运行位置改用 `variant="outlined"`。
- `agent/tools/ProposalApproval.tsx`：拒绝改为 outlined，一张卡只留一个强调色。
- `admin.css`：删掉 `.admin-form` 的背景、圆角与内边距（表单列与标题齐平，错色补丁消失）；`.admin-card p` → `.admin-card>p`，并给卡片 eyebrow 与页头一致的 `.04em` 字距。
- `Admin.tsx`：角色、账号状态、Provider 状态按既有约定映射为中文，`not set` → `未设置`，时间戳统一 zh-CN。
- `App.tsx`：作业 ID 复用既有的 `shortID()`。
- `styles.css`：移动端目标卡改为固定 15rem 基准；`.login-card` 按 mdui-dialog 的做法重绑 `--mdui-color-background`，让浮动标签缺口与卡面同色。

## 验证

- `cd web && npm test`：24 个文件 166 个测试通过；`npm run build`（含 `tsc -b`）通过；`go build ./...` 通过（本轮未改 Go 代码）。
- 针对**构建产物**的 31 条渲染断言全部通过：harness bar 56px 且 `border-bottom:0`、下拉为 outlined 且容器不再绘制填充面、表格单元格竖线 0px 而行 hairline 1px、表头与斑马纹背景均透明、提案卡背景透明且保留 1px 边框、决策按钮为 filled+outlined、会话行无日期元素、后台表单无底色且 eyebrow 12px < h3 14px 且为中文、后台/对话框/登录卡三处标签缺口与所在面同色、作业 ID ≤20 字符、移动端三张目标卡都是 240px、触摸端图标 ≥34px、操作层 `position:static`、标题与操作层零重叠、400px 无横向溢出。
- 21 个场景（1440 浅色/深色、400 浅色 × 7 个标签页，另含目标地图与登录页截图）横向溢出均为 0。
- 局限：headless chromium 恒返回 `hover:none`，桌面端 `(hover:hover)` 的悬停覆盖分支无法在本环境实测，本轮未改其行为，只更新了注释。

## 部署

- 生产前端由 `efe3da2` 的产物（`index-2oJgFzgh.js` / `index-BwsYax8Y.css`）切换为本轮产物（`index-Cii9LK4N.js` / `index-kp8iHCLh.css`）。服务进程按请求从磁盘读取 `web/dist`（`internal/config/config.go` 默认值 + `internal/httpapi/server.go` 的静态处理），所以切换不需要重启后端；本轮没有数据库迁移和 Go 代码变更，也没有改 sidecar 依赖的 `web/src/harness/`。
- 与 `.gitignore` 里记录的 `web/dist.new` 暂存流程不同，本轮直接构建进 `web/dist`，构建到复核之间约一分钟；下次仍应先构建到 `web/dist.new` 再改名，避免构建清目录的瞬间被请求命中。
- 回滚件：按 `efe3da2` 源码重新构建并核对哈希与切换前一致，存于 `backups/web-dist-efe3da2-before-polish`，覆盖回 `web/dist` 即可回滚。
- 复核实际监听地址与公网地址：`/`、`/assets/index-Cii9LK4N.js`、`/assets/index-kp8iHCLh.css`、`/sw.js`、`/fx-core.wasm`、`/health/ready` 均为 200，首页引用的正是新哈希。
- 本轮没有在浏览器里执行登录以外的写操作（创建、修改、删除、审批），因此不宣称完成生产全操作 QA；只读渲染复核覆盖 7 个标签页、3 种视口与深浅两套主题。
