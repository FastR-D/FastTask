# FastTask 功能设计

> 文档状态：初版设计  
> 产品名称：FastTask / 3Signals  
> 需求依据：`doc/req/overall.md`、`doc/req/this.md`

## 1. 产品概述

FastTask 是 FastResearch 工具体系中的长期目标推进与每日重点任务工具，面向任务抽象、里程碑不明确、方法未知且时间可自主安排的研究生和科研人员。

FastTask 不以收集全部待办和安排全部时间为目标，而是：

1. 帮助用户建立长期目标和里程碑。
2. 由 Agent 将目标持续拆解为可执行任务树。
3. 每天从所有候选任务中选择最多三个最重要的核心推进项。
4. 给出具体执行建议和最差情况下仍可完成的最小行动。
5. 认可结果、关键步骤和真实专注时间三类推进。
6. 根据结果、阻碍和用户反馈持续修正计划。

## 2. 产品原则

1. 每日核心任务最多三个，可以少于三个。
2. 候选不足时不编造任务填满三个名额。
3. 当日计划项是底层任务的当日推进切片，不是底层任务本身。
4. 完成最小行动可以完成当日承诺，但默认不完成底层任务。
5. 完成 2 至 3 个番茄可以满足时间型当日承诺，但默认不完成底层任务。
6. 未完成当日项不原样滚动到第二天，必须重新评估。
7. 任务拆解必须回答“怎么做”，不能只有标题列表。
8. Agent 输出是建议或结构化提案，必须受权限、版本和业务规则约束。
9. 任务树修改必须版本化，并保护历史完成记录。
10. 核心工作与个人杂事解耦，FastTask 不成为另一个无限增长的待办箱。

## 3. 产品范围

### 3.1 MVP 范围

- 用户登录和个人数据隔离。
- 长期目标创建、暂停、恢复、完成和归档。
- Agent 生成里程碑、多层任务树、执行建议和最小行动。
- 用户通过文本对话修正任务树。
- 语音录制、转写、用户确认和提交。
- 手工创建和编辑任务。
- 每日计划及最多三个核心任务。
- 辅助输入任务。
- 结果、步骤、最小行动和时间投入记录。
- 番茄计时。
- 响应式管理界面：登录、今日计划、目标/任务树、对话与语音、番茄、进度、设备设置。
- 墨水屏只读 Poll。
- FastResearch Panel 任务摘要和入口联动。
- Agent Job 状态查询、失败重试和取消。

### 3.2 P1 范围

- 流式语音识别、语音播报和免确认语音操作。
- FastNews、FastRead、FastWrite、FastInsight 的通用事项导入或结果引用已实现；FastLabs、FastPPT 和专用双向适配器仍待后续确认。
- 浏览器、飞书、邮件或移动推送提醒。
- 团队共享目标和协作权限。
- 墨水屏写回完成状态。
- 附件、图片和复杂成果管理。
- 更完整的周报、复盘和长期趋势分析。

### 3.3 非目标

- 通用个人生活待办。
- 全天日程排程。
- 绩效考核或工时排名。
- 自动判断科研成果的学术正确性。
- 自动替用户完成科研工作。
- 通用 Agent DAG 编排。

## 4. 角色与权限

### 4.1 普通用户

可以：

- 管理自己的目标、任务树、每日计划和进度。
- 发起 Agent 拆解和修正。
- 提交结果、步骤、阻碍和时间记录。
- 管理自己的墨水屏设备。
- 查看自己的 Agent Job 和历史记录。

不能：

- 查看或修改其他用户的私人数据。
- 修改系统 Agent、认证和服务集成配置。
- 使用设备 Token 调用用户写接口。

### 4.2 管理员

可以：

- 管理账号、服务配置、失败作业和设备撤销。
- 查看服务健康、审计记录和必要的运行信息。

默认不能读取普通用户的私人任务正文。团队共享需求应使用独立授权，不因管理员身份自动开放全部内容。

### 4.3 Agent

可以：

- 生成目标澄清问题、里程碑、任务树、执行建议和最小行动。
- 对任务优先级、阻碍和每日候选进行结构化分析。
- 根据用户反馈生成变更提案。

不能：

- 绕过权限读取其他用户数据。
- 删除历史进度证据。
- 静默覆盖新版本任务树。
- 编造不存在的完成事实。
- 在候选不足时伪造核心任务。
- 未经用户确认完成长期目标或执行高影响结构变更。

### 4.4 墨水屏设备

MVP 为只读角色，仅可读取绑定用户当天最多三个核心任务及显示所需信息。

### 4.5 FastResearch Panel

MVP 只读取当前用户的 FastTask 摘要并提供入口，不直接修改任务状态，不直接访问数据库。

## 5. 核心术语

| 术语 | 定义 |
|---|---|
| 长期目标 | 数周或数月推进、初始方法可能未知的高层目标 |
| 里程碑 | 长期目标中的阶段性、可验证结果 |
| 任务树 | 目标、里程碑、任务和子任务的层级结构 |
| 底层任务 | 持久存在、可跨多日推进的真实工作任务 |
| 当日计划 | 某用户在某个本地日期的执行计划快照 |
| 核心计划项 | 当天最重要的推进项，最多三个 |
| 辅助输入任务 | 阅读、学习、资料收集等服务于目标的输入任务 |
| 当日承诺 | 当天期望达到的具体推进范围 |
| 最小行动 | 时间或状态很差时仍能立即执行的最小有效动作 |
| 执行建议 | 第一阶段怎么开始、步骤、预期结果、受阻替代方案 |
| 进度证据 | 结果摘要、步骤、文件链接、计时、日志或阻碍说明 |
| 当日承诺完成 | 满足该日计划项的约定，不必完成底层任务 |
| 底层任务完成 | 满足任务最终验收条件并得到确认 |

## 6. 长期目标

### 6.1 创建目标

用户可通过表单或对话描述长期目标。系统至少收集：

- 标题和目标描述。
- 期望成果或验收条件。
- 可选目标日期。
- 当前已有基础和约束。
- 每周或每日大致可投入时间，可选。

信息不足时，Agent 应提出澄清问题或明确标记假设，不能将假设当作已确认事实。

### 6.2 目标状态

```text
draft -> active -> completed -> archived
             |-> paused -> active
             |-> abandoned -> archived
```

| 状态 | 含义 |
|---|---|
| `draft` | 尚未形成有效计划 |
| `active` | 可参与任务拆解和每日计划 |
| `paused` | 暂停，不参与每日候选 |
| `completed` | 用户确认目标已完成 |
| `abandoned` | 用户确认放弃目标 |
| `archived` | 只读历史记录 |

长期目标原则上由用户确认完成。当前任务全部完成只能触发完成建议，不能自动完成目标。

`archived` 是只读存储状态。MVP 只允许 `completed` 或 `abandoned` 目标进入 `archived`；进行中的目标应先暂停、完成或放弃，不能用归档绕过状态语义。

## 7. 任务树与里程碑

### 7.1 Agent 拆解输出

Agent 应输出结构化内容：

- 目标验收条件和当前假设。
- 阶段性里程碑。
- 里程碑下的任务和子任务。
- 当前可执行叶子任务。
- 任务依赖和阻碍。
- 每个任务的完成标准。
- 执行建议、预计投入范围和最小行动。

远期任务可保持较粗粒度，当前一至两周的任务应更具体。未知性高的工作应拆成探索或验证任务，而不是伪造确定路线。

### 7.2 任务节点字段

每个任务至少包含：

- 稳定 ID、标题、描述。
- 所属目标、里程碑和父任务。
- 状态、优先级和排序。
- 完成标准。
- 执行建议和最小行动。
- 预计投入范围。
- 依赖、阻碍和允许进入每日候选的标志。
- 创建来源、任务树 Revision 和审计时间。

### 7.3 拆解质量规则

- 任务必须有可观察的推进结果。
- 当前叶子任务应可在一次或少数几次专注工作中推进。
- 不机械拆成大量没有业务意义的点击动作。
- 最小行动可以很小，但必须与真实任务有直接关系。
- 连续无法推进时优先检查粒度、依赖和路线，而不是继续催促。
- 任务标题和执行建议不能只是“研究一下”“继续推进”等空泛描述。

### 7.4 任务树版本化

以下变化创建新 Revision：

- 新增、删除、拆分、合并或移动节点。
- 修改依赖关系。
- 实质修改完成标准。
- 更换技术路线或主要里程碑。
- 将任务标记为被替代或不再需要。

Revision 记录创建者、时间、原因、摘要、上一 Revision、Agent Job 和确认状态。

### 7.5 历史保护

- 已完成任务不物理删除。
- 历史标题、完成标准和进度证据保留。
- 新拆出的任务使用新 ID。
- 历史当日计划继续引用其生成时的快照和任务树 Revision。
- 误完成通过撤销事件纠正，不直接覆盖原记录。

## 8. Agent 规划与修正

### 8.1 触发条件

- 用户新建目标并请求拆解。
- 用户认为任务过大、不可行或顺序错误。
- 出现新的约束、失败结果或技术阻碍。
- 连续多日未产生标准进展。
- 实际投入显著超过预估。
- 当前路线被实验结果否定。
- 任务缺少完成标准或合法最小行动。

### 8.2 可提议变更

- 拆分、合并、移动或暂停任务。
- 新增探索任务或解除阻碍任务。
- 调整依赖、优先级和预计投入。
- 改写执行建议、最小行动和当日承诺。
- 替换失效路线或里程碑。

### 8.3 确认规则

MVP 设计决策：所有结构性任务树变更均先生成提案，由用户确认后生效。

补充说明、执行建议和不改变业务含义的文本修正可配置为自动生效，但仍记录 Revision。

### 8.4 Agent 失败降级

- 已有任务和计划仍可读写。
- 用户可手工创建、修改和选择任务。
- 不合法或不完整的 Agent 输出不进入正式数据。
- Job 显示失败原因和是否可重试。
- 墨水屏继续显示最近一次有效计划及更新时间。

## 9. 每日计划

### 9.1 计划定位

每日计划不是完整日程，而是当天最重要工作的承诺集合。核心计划项理想上可在约两小时内形成明显推进，但系统不强制安排剩余时间。

### 9.2 核心数量

- 核心计划项数量为 0 至 3。
- 候选只有一个或两个时按实际数量返回。
- 候选为零时生成合法空计划，并说明原因。
- 辅助输入任务不占核心名额。
- 同一天完成核心项后不得继续追加新的核心项绕过上限；可追加辅助项。
- 计划项创建后不能修改 `kind`；需要改变类型时创建新计划 Revision。当天核心名额按“已满足核心项 + 当前 Revision 中未满足的有效核心项”计算，未满足且在重规划中被替换为 `superseded` 的项不再占当前名额，已满足项继续占用名额。

“0 至 3 个”是对原始“三个任务”需求的设计解释：三个是上限。候选不足时若强制补满，会产生与长期目标无关的伪任务。

### 9.3 当日计划项

每个核心项至少包含：

- 当日项 ID 和底层任务 ID。
- 所属目标和里程碑。
- 标题、入选原因和当日承诺。
- 推荐步骤、预计投入和番茄数量。
- 最小行动。
- 可接受的完成方式。
- 计划和任务树 Revision。

### 9.4 计划状态

```text
draft -> active -> closed
   |        |-> superseded
   |-> cancelled
```

同一天可以有多个历史版本，但同一时刻只有一个当前版本。重规划不得删除旧计划和已经产生的进度记录。

## 10. 日计划生成规则

### 10.1 总体原则

Agent 可以理解语义并提供结构化分析，但最终候选过滤、排序、去重和最多取三个必须由确定性程序完成。

相同用户、日期、时区、任务树 Revision、状态快照、版本化 Agent 分析快照、配置和算法版本应生成相同结果。Agent 分析一旦进入本次计划输入就固定并保存内容哈希，不在同一次确定性排序中重复生成。

### 10.2 候选过滤

候选任务必须：

- 属于 `active` 目标。
- 未完成、未取消、未归档或被替代。
- 允许进入核心候选。
- 强依赖已满足。
- 没有导致当天完全不可行动的硬阻碍。
- 有明确当日推进方式和合法最小行动。
- 不是与目标无关的个人杂事。
- 未被用户明确排除。

如当天可做的是“申请权限”“定位报错”等解除阻碍动作，应将其建模为真实任务，而不是忽略阻碍直接选择原任务。

### 10.3 确定性排序

MVP 建议依次比较：

1. 用户当天明确指定。
2. 临近目标日期或里程碑风险。
3. 任务优先级。
4. 是否位于当前关键路径。
5. 是否能解除多个任务阻碍。
6. 距离上次实质推进时间。
7. 是否延续前一日有效进展，但不得机械顺延。
8. 与用户当天可用时间的适配度。
9. 创建时间。
10. 稳定任务 ID 作为最终平局裁决。

权重和算法版本必须固定并保存，Agent 不得每次临时改变排序逻辑。

### 10.4 用户约束

用户可指定当天必须优先或排除的任务，但仍不得违反权限、硬依赖和最多三个核心项。

用户指定超过三个时，系统要求用户选择，或根据确定性规则保留前三项并明确告知未入选项。

### 10.5 候选不足

不生成“思考一下”“阅读一些资料”等占位任务。系统应给出原因及可选操作：创建目标、解除阻碍、细化任务树、恢复目标或请求重新规划。

### 10.6 未完成任务处理

日终后：

1. 保留原计划项并标记未完成。
2. 记录可选未完成原因。
3. 将底层任务重新放回候选评估。
4. 重新检查依赖、阻碍、优先级和粒度。
5. 重新生成当日承诺和最小行动。
6. 决定继续、拆分、暂停、替换或延后。
7. 若再次入选，创建新的当日项 ID。

连续两次未完成时提示修正；连续三次未完成或连续三次只完成最小行动时，建议在再次入选前执行拆分或阻碍诊断。具体阈值允许配置。

## 11. 最小行动与完成语义

### 11.1 最小行动要求

每个核心项必须有一个当前有效最小行动，至少说明：

- 对什么对象执行什么动作。
- 什么状态表示完成。
- 预计时间。
- 与底层任务的关系。

建议控制在 5 至 15 分钟内。不能只是打开应用、点击完成或与任务无关的动作。

### 11.2 当日完成类型

| 类型 | 含义 |
|---|---|
| `result` | 获得了预期结果或产物 |
| `step` | 完成了预定义关键步骤 |
| `time` | 达到预定义有效专注时长 |
| `minimum_action` | 仅完成最小行动 |

当多个条件同时满足时保留全部证据，展示优先级建议为：

```text
result > step > time > minimum_action
```

该级别用于计划调整，不用于用户绩效排名。

### 11.3 底层任务完成

底层任务只有在满足最终完成标准并得到用户确认后完成。仅达到当日时间目标、最小行动或局部步骤不能自动完成底层任务。

Agent 可以建议底层任务完成，但不能自行确认长期任务完成。

## 12. 番茄与专注时间

### 12.1 MVP 功能

- 从任务或当日计划项开始计时。
- 默认 25 分钟，可自定义。
- 暂停、继续、提前结束、正常完成和标记无效。
- 页面刷新后恢复服务端活动 Session。
- 记录开始、结束、有效时长和结束反馈。
- 同一用户默认最多一个活动 Session。

### 12.2 时间型完成

达到计划项预先设定的目标时长可以满足当日项。结束后用户至少选择：

- 有结果。
- 有步骤进展。
- 遇到阻碍。
- 无有效进展。

系统不完全信任客户端提交的秒数，最终时长由服务端 Session 计算。异常超长 Session 要求用户确认有效时长。

## 13. 辅助输入任务

非核心任务分为：

- `support`：解除阻碍、整理环境、请求权限等辅助工作。
- `input`：阅读论文、学习工具、收集资料等科研输入。

二者都不占核心名额。

规则：

- 与目标或当前里程碑有关。
- 说明输入内容服务于什么问题。
- 有范围和建议时长。
- 默认在核心任务之后展示。
- 不计入核心完成率，不替代未完成核心任务。
- 候选不足时不生成。
- MVP 建议每天最多展示三个，默认一至两个。
- 系统自动分配 `support/input` 的触发点是当天全部核心项已满足之后；此前不主动用辅助任务分散注意力。

## 14. 对话与语音

### 14.1 文本对话

用户可以：

- 创建目标。
- 查询今天最重要的任务及入选原因。
- 报告进展和阻碍。
- 请求拆分、合并、重排、暂停或替换任务。
- 请求重新生成执行建议或当日计划。

涉及状态修改时，系统展示结构化操作、目标对象、前后差异和是否影响当前计划。讨论可能性不等于执行命令。

### 14.2 语音输入

MVP 最低要求：

- 用户可以录制并上传语音。
- 系统异步转写。
- 用户可以查看、编辑并确认转写文本。
- 确认后按文本对话规则提交。
- 转写失败可重试或改用文字。

语音不能绕过结构化确认和权限校验。流式识别、播报和免确认操作属于 P1。

## 15. 进度可视化

### 15.1 长期目标视图

- 当前目标和状态。
- 当前里程碑和验收条件。
- 当前关键任务和阻碍。
- 最近有效进展。
- 任务树 Revision 和修改历史。

### 15.2 任务树视图

- 多层级展开和折叠。
- 状态、依赖、完成标准和执行建议。
- 历史进度证据。
- 拆分、合并和被替代关系。
- 从节点发起对话修正。

### 15.3 每日视图

- 最多三个核心项。
- 当日承诺、最小行动和推荐步骤。
- 预计番茄、实际投入和完成类型。
- 辅助输入任务。
- 计划生成原因、算法版本和计划 Revision。

### 15.4 指标原则

可以展示里程碑状态、最近七天有效推进天数、完成类型分布、阻碍和停滞任务。

不得：

- 将当日项完成数等同于长期目标完成率。
- 用叶子任务数量简单计算科研目标百分比。
- 将最小行动完成显示为底层任务完成。
- 用单一百分比制造虚假精确感。

## 16. 墨水屏

### 16.1 MVP 能力

- 每台设备使用独立设备 Token。
- 轮询绑定用户当前本地日期的计划。
- 返回最多三个核心项、标题、最小行动、状态和更新时间。
- 使用 `ETag`，内容未变化返回 `304`。
- 设备离线保留最后一次内容，并展示数据时间。

### 16.2 安全规则

- Token 只允许读取绑定用户的设备视图。
- Token 仅创建或轮换时显示一次，服务端保存哈希。
- 支持撤销、轮换、限流和访问审计。
- 不返回完整任务树、对话、Prompt 或敏感进度证据。

### 16.3 P1

- 从墨水屏标记完成。
- 主动推送。
- 语音输入。
- 多页面任务树和固件管理。

## 17. FastResearch Panel 联动

MVP：

- 显示 FastTask 入口。
- 显示今日核心项总数、完成数、当前任务、阻碍状态和更新时间。
- 使用统一用户标识或短期登录 Token。
- Panel 只调用只读摘要接口，不直接访问 FastTask 数据库。

与 FastNews、FastRead 等其他工具的自动点对点调用未在需求中明确。当前已实现通用导入收件箱和 FastRead/FastWrite 可选健康探测，不假设特定双向同步协议。

## 18. 状态机

### 18.1 底层任务

```text
draft -> ready -> in_progress -> completed
          |          |-> blocked -> ready/in_progress
          |          |-> paused -> ready/in_progress
          |-> cancelled
          |-> superseded
completed/cancelled/superseded -> archived
```

完成、撤销完成和状态回退必须有审计事件。

### 18.2 当日计划项

```text
planned -> in_progress -> satisfied
   |            |-> not_completed
   |-> skipped
   |-> superseded
```

`satisfied` 必须记录完成类型；日终关闭计划时，未满足的 `planned/in_progress` 项转为 `not_completed`；同日重规划中被替换的项转为 `superseded`；`not_completed` 不自动复制到下一天。

### 18.3 Work Session

```text
running -> paused -> running
running/paused -> completed
running/paused -> stopped
completed/stopped -> invalidated
```

### 18.4 Agent Job

```text
queued -> running -> succeeded
                  -> queued（重试）
                  -> failed
queued/running -> cancelled
failed -> 新建 queued Job（手工重试）
```

自动重试复用原 Job 并增加 Attempt；手工重试创建新 Job，通过 `retry_of_job_id` 关联原失败 Job，原 Job 状态保持 `failed`。版本冲突必须基于最新资源创建新 Job。

## 19. 异常与边界

| 场景 | 处理 |
|---|---|
| 没有长期目标 | 返回空计划，引导创建目标 |
| 所有目标暂停 | 返回空计划并说明原因 |
| 所有任务阻塞 | 返回可执行解除阻碍任务或空计划 |
| 任务无完成标准 | 不允许自动完成，建议补充标准 |
| 任务无合法最小行动 | 不进入核心候选，先拆分或补充 |
| 用户当天不可用 | 生成零核心项，不形成未完成记录 |
| 同日重规划 | 创建新计划 Revision，保留已完成和计时记录 |
| 执行中修改任务树 | Session 保持关联原任务和 Revision，不静默迁移 |
| 误完成 | 创建撤销/纠正事件，不删除原事实 |
| Agent 超时或输出损坏 | Job 失败，正式数据不变，可重试或手工处理 |
| Agent 结果版本过期 | 标记冲突，不覆盖新任务树 |
| 墨水屏离线 | 使用最后缓存，联网后按 ETag 同步 |
| 跨时区 | 历史计划日期不改写，新计划按新时区生成 |

## 20. MVP 验收标准

1. 用户可创建抽象长期目标并发起 Agent 拆解。
2. Agent 可生成结构化里程碑、任务树、执行建议和最小行动。
3. 用户可通过对话生成任务树修改提案并确认生效。
4. 每日计划核心项始终为 0 至 3 个。
5. 候选不足时不生成占位任务。
6. 相同计划输入和算法版本生成相同核心项及顺序。
7. 完成最小行动或时间目标只满足当日项，不误完成底层任务。
8. 用户可提交 result、step、time 和 minimum_action 证据。
9. 未完成当日项不会被原样自动复制到次日。
10. 任务树修改后，历史计划和进度证据仍可查询。
11. Agent 服务失败时用户仍可手工管理任务。
12. 墨水屏可使用设备 Token 和 ETag 获取当前计划。
13. Panel 可使用受控身份获取任务摘要。
14. 用户不能访问其他用户的私人资源。
15. 写操作具有幂等和 Revision 冲突保护。
16. 管理界面在桌面和移动浏览器均可完成核心操作。
17. 用户可录音、确认转写文本并将其作为对话输入。

## 21. 待确认事项

- 产品名称最终使用 FastTask、3Signals 还是二者并列。
- 计划自动生效还是用户首次打开时确认。
- 默认每日计划生成时间。
- 默认时间型完成阈值为 50 分钟还是 75 分钟。
- 辅助输入任务默认上限。
- 用户可同时激活多少长期目标。
- 多目标之间是否需要默认均衡。
- 管理员、导师和团队成员的共享权限。
- 语音识别 Provider、单次音频大小和保留时长。
- Panel 统一认证的签发方和协议。
- 墨水屏设备 Token 有效期及建议轮询频率。
- 是否允许用户完成三个核心项后增加新的核心项。本设计默认不允许。
- 是否允许低风险任务树文本修正自动生效。本设计建议结构变化全部确认。
