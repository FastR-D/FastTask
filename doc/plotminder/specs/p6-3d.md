# Feature Spec: P6 3D Maps

**Phase**: P6
**Milestone**: Future (post v1.0)
**Status**: Draft (placeholder)
**Created**: 2026-05-19
**Constitution Compliance**: v1.0.0
**Dependencies**: P0, P1, P2, P3

---

## 1. 概述

P6 引入**第三条用户自定义的语义轴**,把决策地图从二维平面升级为三维空间。原始构想来自产品 raw note:"喜爱程度"作为第三维。

P6 不是简单的 UI 增强——它要求 view 数据模型扩展、3D 渲染、3D 拖拽手势、2D↔3D 视图切换。

P6 是"锦上添花"phase,**不是 v1.0 必需**。本 spec 作为 Future placeholder,版本号为 0.1,完整 spec 在进入 P6 前重新起草。

成功标志:**用户能为 view 配置第三条轴(例如"喜爱程度"),在 3D 空间中拖动节点,且能随时投影回 2D 看任意两条轴的组合**。

---

## 2. 用户故事

- **US-P6-1** 作为用户,我能在 view 配置中添加第三条轴(轴名、description、ideal corner 方位)。
- **US-P6-2** 作为用户,我能切换该 view 为 3D 视图,看到 task 在三维空间中的分布。
- **US-P6-3** 作为用户,我能用鼠标(或触摸)在 3D 空间中拖拽节点,改变三轴坐标。
- **US-P6-4** 作为用户,我能用轨道相机(orbit camera)从不同角度观察 3D 地图。
- **US-P6-5** 作为用户,我能随时从 3D 投影回 2D,选择任意两条轴的组合作为 2D 视图。
- **US-P6-6** 作为用户,我能在 3D 视图下看到推荐路径(P3 的路径推荐算法扩展到三维)。

---

## 3. 功能需求(轮廓级,待 P6 阶段细化)

### 3.1 View 数据模型扩展

- **FR-P6-001** `View.axes` 数组支持 2 或 3 个轴(P2 已为此预留)。
- **FR-P6-002** `TaskViewPlacement` 的 `z` 字段(P0 已建模为可选)在 P6 启用。
- **FR-P6-003** 2D view 升级为 3D 时,所有 task 的 z 默认为 50(中点),用户可拖动调整。

### 3.2 3D 渲染

- **FR-P6-004** 使用平台原生 3D 能力(Flutter 的 Scene API、Metal/OpenGL/Vulkan 后端);评估是否需要引入 Flame 或 three_dart 之类的库。
- **FR-P6-005** 节点视觉编码(P1)在 3D 中保留:位置(x,y,z)、大小、颜色、形状、透明度。
- **FR-P6-006** 3D 场景的视觉风格保持与 2D 一致(同一套色系、字体、节点样式)。

### 3.3 3D 交互

- **FR-P6-007** 拖拽:在 3D 中拖拽节点的语义复杂(屏幕鼠标移动需要映射到 3D 平面)。基础策略:
  - 默认拖在屏幕平行平面(与相机正交)上
  - 修饰键(Shift / Cmd)切换约束到 X / Y / Z 单轴
- **FR-P6-008** 相机控制:
  - 右键拖 = orbit
  - 中键拖(或两指) = pan
  - 滚轮(或捏合) = zoom
- **FR-P6-009** 触屏支持:单指拖节点,双指 orbit + pinch zoom。

### 3.4 2D↔3D 切换

- **FR-P6-010** View 配置中提供"View Mode"开关:2D / 3D。
- **FR-P6-011** 2D 模式下用户能选择三轴中的任意两条作为 X/Y。
- **FR-P6-012** 模式切换时有平滑过渡动画(< 500ms)。

### 3.5 路径推荐在 3D

- **FR-P6-013** P3 的算法(Pareto frontier、距 ideal corner 距离)扩展到三维(欧氏距离自然推广,frontier 在三维空间计算)。
- **FR-P6-014** 推荐路径在 3D 视图中以三维曲线呈现。

---

## 4. 非功能需求

- **NFR-P6-001** 3D 渲染在中型机器(M1 Mac、中端 PC、iPhone 12+)上保持 60fps,≤ 500 节点。
- **NFR-P6-002** 低端设备(整合显卡笔记本、Android mid-range)支持降级到 30fps 或 fallback 2D。
- **NFR-P6-003** 3D 模式与 2D 模式在功能完整性上等价(键盘可达性、视觉编码等)。

---

## 5. 验收标准

- **AC-P6-1** 创建 3 轴 view,放入 30 个 task,3D 视图正确渲染,可旋转、缩放、平移。
- **AC-P6-2** 在 3D 视图拖动节点,坐标 (x, y, z) 正确更新并持久化。
- **AC-P6-3** 切换到 2D 模式,选择 X/Z 轴组合,2D 视图正确显示对应投影。
- **AC-P6-4** 推荐路径在 3D 模式下正确显示且符合算法预期。

---

## 6. 范围

### In Scope
- 第三轴 view 配置;3D 渲染;3D 拖拽与相机控制;2D↔3D 切换;路径推荐三维扩展。

### Out of Scope
- N > 3 维度(违反直观可视化原则)
- 虚拟现实(VR)模式(投入产出比不合理)
- 3D 视图下的复杂动画效果(避免炫技伤害可用性)

---

## 7. 依赖

- **前置 phase**: P0、P1、P2、P3(P4/P5 不强依赖,但已存在则 3D 视图也应支持其功能)
- **外部**: Flutter Scene API / 第三方 3D 库

## 8. Constitution Alignment

| 宪章条款 | 关系 | 处理 |
|---------|------|------|
| III (多 view 单 task) | **直接落地** | 同一 task 在 2D view 和 3D view 上各有独立 placement(三维 placement 包含 z) |
| IV.4 (洞察必须可视化) | **强化** | 3D 是更高维度的可视化形式 |
| 约束 A (跨平台一致性) | **挑战点** | 3D 渲染在 5 个平台的性能与一致性是 P6 最大技术挑战 |

**潜在张力点**

- **关于 3D 是否削弱"看见"能力**: 3D 视图的认知开销比 2D 高,可能反而让用户更难一眼看出全局——这点要警惕。处理:**2D 永远是默认**,3D 是 opt-in,且 2D↔3D 切换无摩擦,让用户在哪里更舒服就在哪里。
- **关于第三轴是否会被"AI 提议"添加**: 严格遵守 I.3,系统不主动建议用户升级 view 到 3D;只在 view 编辑器中提供 3D 作为选项。

---

## 9. 开放问题

- **OQ-P6-1** Flutter 的 3D 能力在 P6 启动时是否成熟?如不成熟,是否考虑用 platform view + 原生 3D?
- **OQ-P6-2** 3D 视图的色彩深度感(distance fog、depth of field)如何与 2D 风格统一?
- **OQ-P6-3** 3D 拖拽的精度问题:屏幕一像素的移动可能对应空间中很大的位移;需要 fine-tune 模式(慢拖)。
- **OQ-P6-4** 多视角并存(2D + 3D 分屏)是否值得做?可能用于 power user。
- **OQ-P6-5** 这个 phase 是否应该等 v1.0 稳定 + 用户增长一段时间后再启动?(优先级与定价模型相关)
