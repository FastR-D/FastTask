# Feature Spec: P7 Cloud Sync & Team Workspaces

**Phase**: P7
**Milestone**: Future (post v1.0)
**Status**: Draft (placeholder)
**Created**: 2026-05-19
**Constitution Compliance**: v1.0.0
**Dependencies**: P0–P5(P6 可选)

---

## 1. 概述

P7 实现 Plotminder 的**多设备同步与团队 workspace 雏形**。两件事:**SyncProvider 接口实例化、团队共享(从只读 share 到协同编辑的渐进路径)**。

P7 是 v2.0 的前置铺垫。本 spec 是 Future placeholder,完整 spec 在 v1.0 稳定且用户基数验证团队需求后重新起草。

P7 最敏感的设计点:**云同步是 opt-in,不是默认**(宪章 V.3),且必须 e2e 加密,用户密钥用户掌控,Plotminder 服务器不应能看到用户数据明文。

成功标志:**用户能在 macOS + iPhone + iPad 上看到同一份数据,实时同步;且能与一个搭档共享某 workspace,搭档能看到地图(初期为只读)**。

---

## 2. 用户故事

- **US-P7-1** 作为单兵用户,我能在 Settings 中开启云同步(opt-in),数据在我的设备间同步。
- **US-P7-2** 作为关心隐私的用户,我能确认我的数据在云端是加密的,且 Plotminder 无法解密。
- **US-P7-3** 作为多设备用户,我在 macOS 上拖动节点,iPhone 上同一节点在数秒内更新。
- **US-P7-4** 作为团队成员,我能把某个 workspace 共享给搭档(以邮件邀请),搭档能查看(初期只读)。
- **US-P7-5** 作为团队成员,我能在共享 workspace 中看到搭档的最新更改(协同编辑,如果 P7 范围覆盖)。
- **US-P7-6** 作为用户,我能随时关闭云同步,本地数据保留,云端数据删除。

---

## 3. 功能需求(轮廓级)

### 3.1 SyncProvider 实现

- **FR-P7-001** 实例化 P0 预留的 `SyncProvider` 接口。
- **FR-P7-002** 采用基于 CRDT 或 Operation Log 的同步策略(待技术评估):
  - **CRDT 优势**:offline-first 自然支持,无冲突合并
  - **Op Log 优势**:简单、便于审计、对开发者友好
- **FR-P7-003** 同步频率:
  - 主动写入立即推送(乐观推送,失败 retry)
  - 后台拉取每 30 秒(可调)
  - 启动时强制全量校验

### 3.2 端到端加密

- **FR-P7-004** 用户数据在客户端加密,Plotminder 服务器只存密文。
- **FR-P7-005** 加密密钥派生策略候选(待评估):
  - **基于用户密码**:简单,但忘记密码 = 数据永久丢失
  - **基于设备密钥 + 服务端混合**:可恢复,但增加信任 vector
  - **iCloud Keychain / Google 密钥同步**:省事但绑死生态
- **FR-P7-006** 元数据(workspace 名、share 关系)最小化加密(便于 Plotminder 提供服务)。
- **FR-P7-007** 任何同步功能 opt-in,默认关。

### 3.3 多设备同步

- **FR-P7-008** 用户在某设备登录账户后,该设备列入"已授权设备"。
- **FR-P7-009** 用户能在 Settings → Devices 查看所有已授权设备,撤销任一设备的访问。
- **FR-P7-010** 设备首次同步后增量更新;断网期间本地累积变更,网络恢复后批量同步。
- **FR-P7-011** 冲突解决沿用 P4 的策略(last-write-wins + changelog + 冲突 UI),但语义在 CRDT 上重新定义。

### 3.4 团队 Workspace(初期)

- **FR-P7-012** 用户能"分享" workspace 给另一个 Plotminder 用户(邮件邀请,接收方需注册账户)。
- **FR-P7-013** 分享权限初期支持:**view-only**(只读)。
- **FR-P7-014** 共享 workspace 的所有者保留完整控制权;协作者只能查看。
- **FR-P7-015** (可选,视 v2 范围)协同编辑:多人能同时拖拽节点,通过 CRDT 收敛。
- **FR-P7-016** Activity feed:谁、什么时候、改了什么,在共享 workspace 中可见。

### 3.5 离线与降级

- **FR-P7-017** 任何同步失败不阻塞本地使用(宪章 V.2);失败的同步进 retry 队列。
- **FR-P7-018** 服务端不可达时,客户端持续本地工作;客户端不显示焦虑提示,只在 Settings 显示同步状态。
- **FR-P7-019** 用户能随时关闭云同步,所有本地数据保留,云端数据按用户指令删除(GDPR 兼容)。

### 3.6 计费

- **FR-P7-020** 云同步是付费功能(Plus 计划及以上,见定价文档)。
- **FR-P7-021** 团队共享是高级付费功能(Pro 计划或专门 Team 计划)。

## 4. 非功能需求

- **NFR-P7-001** 同步延迟 P95 < 5 秒(变更推送到所有设备)。
- **NFR-P7-002** 端到端加密的 KMS / 密钥管理通过第三方安全审计。
- **NFR-P7-003** 服务端 SLA 99.5%(初期),后续提升。
- **NFR-P7-004** 数据传输 TLS 1.3+;数据静态存储于加密 S3 或等价服务。
- **NFR-P7-005** 用户撤销设备后,该设备 5 分钟内失去数据访问。

---

## 5. 验收标准

- **AC-P7-1** 用户开启云同步后,在两台设备上数据保持一致;一台设备的拖拽变更在另一台设备上 5 秒内显示。
- **AC-P7-2** 拔网线后在 A 设备上多次修改,网线接回,变更正确同步到 B 设备。
- **AC-P7-3** 用户分享 workspace 给搭档,搭档登录后能看到 workspace 内容(只读)。
- **AC-P7-4** 用户在 Settings 关闭云同步,本地数据完整保留,云端数据按指令删除(可在隐私设置验证)。
- **AC-P7-5** 服务端故障注入测试:服务器返回 5xx,客户端继续本地工作,不显示错误弹窗。

## 6. 范围

### In Scope
- SyncProvider 实例化(CRDT 或 Op Log,待评估);e2e 加密;多设备同步;团队 workspace 共享(初期只读,可选协同编辑)。

### Out of Scope
- 自托管服务器(self-hosted,可能 v3 考虑)
- 跨账户复杂权限(role-based access control v2)
- 实时光标(co-editing 视觉光标,Notion-style)
- 企业级功能(SSO、audit log、admin console)

## 8. Constitution Alignment

| 宪章条款 | 关系 | 处理 |
|---------|------|------|
| V.1 (本地存储为主) | **关键保护** | 云同步是 opt-in,本地数据始终是权威源之一 |
| V.2 (离线核心功能) | **关键保护** | FR-P7-017、FR-P7-018、AC-P7-5 |
| V.3 (云同步 opt-in) | **直接落地** | FR-P7-007、FR-P7-020 |
| I.3 (永不偷偷改数据) | **加强保护** | 协同编辑下"对方改了我的数据"的语义,需要细致 UX 设计 |
| 约束 A (跨平台一致性) | **挑战** | 同步引擎在 5 个平台行为必须一致 |

**潜在张力点**

- **关于团队共享是否打开多人协作的潘多拉盒子**: 宪章第四部分明确"B.3 复杂团队协作 v2 再议"。P7 仅做 view-only 共享 + 可选的简单协同,**不**做 role-based access、permissions matrix、企业管理。任何超出此范围的功能必须修宪。
- **关于云端解密能力**: 严格 e2e 加密意味着 Plotminder 服务器**无法**解密用户数据,这限制了某些服务(如服务端的 AI 总结)。处理:涉及 AI 的功能继续在客户端完成(LLM 调用从客户端发起),服务端只负责密文存储与转发。
- **关于密码丢失即数据丢失**: 如果选择基于用户密码的加密派生,用户忘记密码 = 数据永久无法恢复。需要权衡:用户体验 vs 真正的 zero-knowledge。可能引入"恢复密钥"机制(用户打印保存 24 词助记词)。

## 9. 开放问题

- **OQ-P7-1** 同步引擎选型:CRDT(Yjs / Automerge)vs Operation Log vs 自研?各有权衡。
- **OQ-P7-2** 密钥派生策略:zero-knowledge vs 可恢复性的取舍。
- **OQ-P7-3** 团队协作的 v1 范围:严格只读 vs 简单协同编辑?后者难度大很多。
- **OQ-P7-4** 服务端技术栈:与 Go core 一致(便于代码共享)vs 用其他语言?
- **OQ-P7-5** 计费基础设施:Stripe / Lemon Squeezy / Paddle?定价文档之后专门讨论。
- **OQ-P7-6** GDPR / CCPA 合规要求的具体实现:数据出口、删除请求处理。
