# Feature Spec: P1 MapView

**Phase**: P1
**Milestone**: Alpha (Internal)
**Status**: Draft
**Created**: 2026-05-19
**Constitution Compliance**: v1.0.0
**Dependencies**: P0 Foundation

---

## 1. 概述

P1 把 P0 的数据模型变成**可交互的二维决策地图**。用户能在地图上看见所有 task,拖拽它们改变坐标,缩放、框选、勾掉。本 phase 完成三个核心用户时刻:**The Open(打开瞬间)、The Sort(整理瞬间)、The Complete(完成瞬间)**。

P1 暂不涉及自定义轴(P2)、LLM 打分(P2)、路径推荐(P3)。地图使用一个 hardcoded 的 Eisenhower view(重要 × 紧急)作为默认观察视角。

P1 的成功标志是:**一个用户能在地图上手动管理 50–100 个 task,且觉得拖拽响应流畅、视觉信息清晰**。

---

## 2. 用户故事

- **US-P1-1** 作为用户,我打开 Plotminder 看到当前 view 的二维地图,一眼看出哪些 task 在哪个象限。
- **US-P1-2** 作为用户,我能用鼠标(或触摸)拖动 task 节点,坐标随之改变并立即持久化。
- **US-P1-3** 作为 power user,我能用 Shift / Cmd 修饰键约束拖拽只改单轴,框选批量调整多个节点的坐标。
- **US-P1-4** 作为用户,我能双指(或滚轮)缩放地图,看本周细节或看季度全局。
- **US-P1-5** 作为用户,我能双击节点打开 detail panel,查看/编辑 title、description、tags、status。
- **US-P1-6** 作为用户,我能用键盘 Tab/方向键导航节点、Enter 切换状态,完全不碰鼠标也能用。
- **US-P1-7** 作为用户,我勾掉一个 task 时,它的节点褪色但留在地图上直到周末——让我能感觉到"今天确实做了事"。
- **US-P1-8** 作为用户,长期未更新的 task 会自动变得淡化("年久失修"视觉信号)。

## 3. 功能需求

### 3.1 地图渲染

- **FR-P1-001** 地图以二维笛卡尔坐标系渲染,默认轴为重要(x: 0–100) × 紧急(y: 0–100)。
- **FR-P1-002** 默认 ideal corner 为右上(高重要 + 高紧急)。
- **FR-P1-003** 节点的位置 (x, y) 直接映射到屏幕坐标(经缩放变换)。
- **FR-P1-004** 节点视觉编码(见 §3.2)在所有缩放级别保持可读性。
- **FR-P1-005** 地图必须支持:
  - 拖动平移(空白处拖)
  - 双指 / 滚轮缩放(支持 zoom-to-cursor)
  - 双指旋转禁用(避免误操作)
  - "适应窗口" 按钮一键 reset

### 3.2 节点视觉编码

| 视觉属性 | 编码内容 | 取值规则 |
|---------|---------|---------|
| 位置 (x, y) | view 上的坐标 | 0–100 连续 |
| 大小 | duration estimate | 默认中等;用户可设置 small/medium/large/xl |
| 颜色 | status | todo: 主色;doing: 主色 + 脉冲;done: 灰;archived: 隐藏 |
| 形状/边框 | type | task: 实心圆;event: 方形;idea: 虚线圆 |
| 透明度 | 距 `updated_at` 时间 | < 7 天: 100%;7–30 天: 80%;> 30 天: 50% |

- **FR-P1-006** 视觉编码规则统一从 Go core 提供的辅助函数计算,UI 层不重新发明逻辑。
- **FR-P1-007** 节点上必须显示 task 的 title 缩略(最多 N 字符,N 随 zoom 级别变化)。
- **FR-P1-008** 鼠标悬停(或长按)节点显示 tooltip,含完整 title 与坐标值。

### 3.3 拖拽交互(The Sort)

- **FR-P1-009** 拖动单个节点:鼠标按下 + 移动 + 释放,坐标实时更新并在释放时持久化。
- **FR-P1-010** Shift + 拖:只改 X 轴(锁定 Y)。
- **FR-P1-011** Cmd / Ctrl + 拖:只改 Y 轴(锁定 X)。
- **FR-P1-012** 框选 + 拖:对选中的所有节点应用相同的 (Δx, Δy)。
- **FR-P1-013** 拖拽期间显示坐标值实时反馈(在节点旁或 status bar)。
- **FR-P1-014** 拖拽必须有撤销/重做支持(Cmd/Ctrl + Z / Shift+Z)。
- **FR-P1-015** 坐标值约束在 0–100;超出边界时夹取(clamp)。

### 3.4 选择与批量操作

- **FR-P1-016** 单击节点 = 选中;Cmd/Ctrl + 单击 = 多选;Shift + 单击 = 区域选择。
- **FR-P1-017** 在地图空白处拖出矩形 = 框选所有矩形内节点。
- **FR-P1-018** 批量操作菜单:批量改 status、批量加 tag、批量删除、批量移动。

### 3.5 Detail Panel

- **FR-P1-019** 双击节点(或选中后按 Enter)打开 detail panel,可编辑:title、description、note、tags、status、duration estimate、type。
- **FR-P1-020** Detail panel 可显示 task 在**其他 view** 上的坐标(只读,跳转链接,为 P2 多 view 做准备)。
- **FR-P1-021** Detail panel 修改任何字段后立即保存(无显式 save 按钮)。

### 3.6 状态切换(The Complete)

- **FR-P1-022** 在节点上点击复选框(或按 Space 键)切换 todo ↔ doing ↔ done。
- **FR-P1-023** 切换到 done 时播放一个轻微的微动画(节点褪色 + 短暂高亮),持续 ≤ 400ms。
- **FR-P1-024** Done 节点保留在地图上**直到本地时间周日 24:00**,之后自动归档(从 map 隐藏,数据仍在)。
- **FR-P1-025** "本周已完成"区域(地图角落或独立侧栏)实时展示本周已完成数量。

### 3.7 键盘可达性

- **FR-P1-026** Tab / Shift+Tab 在节点之间导航(按坐标顺序或 z-order)。
- **FR-P1-027** 方向键移动当前选中节点(默认步长 1 个单位,Shift+方向键 = 5 个单位)。
- **FR-P1-028** Enter = 打开 detail panel;Space = 切换 done;Backspace/Delete = archive。
- **FR-P1-029** Cmd/Ctrl + A = 全选当前 view 可见节点。
- **FR-P1-030** Cmd/Ctrl + Z / Shift+Z = 撤销/重做。
- **FR-P1-031** Cmd/Ctrl + N = 新建 task(在地图中心,或上次手动放置位置)。

### 3.8 默认 view

- **FR-P1-032** 首次启动后默认 view 为 Eisenhower(x: 重要, y: 紧急, ideal corner: 右上)。
- **FR-P1-033** P1 仅支持**单 view**;view 切换 UI 在 P2 启用。

## 4. 非功能需求

- **NFR-P1-001** 拖拽响应延迟 < 16ms (60fps)——宪章质量底线。
- **NFR-P1-002** 节点数量 ≤ 500 时拖拽、缩放、平移保持 60fps;500–2000 节点允许降级至 30fps;> 2000 节点 P1 不保证。
- **NFR-P1-003** 所有交互可通过键盘完成(无任何鼠标-only 操作)。
- **NFR-P1-004** 触屏平台(iOS/Android)的所有手势与桌面交互保持等价语义。
- **NFR-P1-005** 视觉编码遵循无障碍准则:status 不仅用颜色区分,也用形状/纹理区分;支持 WCAG AA 对比度。

---

## 5. 验收标准

- **AC-P1-1** 用户能从空白启动开始,在 30 秒内创建第一个 task 并把它拖到右上角。
- **AC-P1-2** 在 500 节点的 mock 数据集上,拖拽响应延迟 P95 < 16ms(性能采样工具验证)。
- **AC-P1-3** 撤销链至少支持 50 步,且应用重启后撤销链清空(无需持久化)。
- **AC-P1-4** 完整一周后,周日 24:00 自动归档已完成节点;归档数据仍可在导出 JSON 中找到。
- **AC-P1-5** 使用纯键盘从启动到完成 5 个 task 的"导航 → 改坐标 → 切 done"循环,不接触鼠标。
- **AC-P1-6** 双指缩放在 iOS/Android 自然流畅;桌面端滚轮缩放支持 zoom-to-cursor。
- **AC-P1-7** 修改某节点后 30 天未再触碰,该节点视觉上 50% 透明度(年久失修信号)。

## 6. 范围

### In Scope
- 2D 地图渲染、拖拽、缩放、框选、视觉编码、detail panel、状态切换、键盘可达性、默认 Eisenhower view。

### Out of Scope(本 phase)
- 多 view 切换(留给 P2)
- 自定义轴名(留给 P2)
- LLM 自动打分(留给 P2)
- 依赖关系编辑、路径推荐(留给 P3)
- 番茄计时、Reflect 周复盘(留给 P5)

## 8. Constitution Alignment

| 宪章条款 | 关系 | 处理 |
|---------|------|------|
| IV.1 (看见 > 自动化) | **直接落地** | P1 全部精力放在"让用户看见"上,没有任何自动化 |
| I.3 (永不偷偷改数据) | **核心保护** | 所有坐标变更必须用户主动触发(拖拽、键盘);**绝无**"自动整理"按钮 |
| 质量底线 (拖拽 < 16ms) | **直接落地** | NFR-P1-001、AC-P1-2 |
| 质量底线 (键盘覆盖率 100%) | **直接落地** | FR-P1-026 ~ 031、AC-P1-5 |
| III.4 (per-view 独立坐标) | **基础落地** | FR-P1-020 在 detail panel 留出"其他 view 坐标"占位 |

**潜在张力点**

- **关于 done 节点保留到周日的视觉处理**: 这是宪章未明确规定但符合"看见 > 自动化"的精神;但严格说,"周日 24:00 自动归档"也是一种自动化操作。处理方式:这是显式向用户承诺的行为、可视化清晰、可被用户禁用(Settings 中可关闭),因此不违反宪章 I.3。
