# 甘特图首版需求

状态：首版已实现，并于 2026-11-10 部署到测试环境。测试与部署记录见 [gantt-testing.md](gantt-testing.md)。

## 目标与范围

为单个科研目标提供长期计划视图，帮助用户查看阶段周期、任务跨度、前置关系和当前状态。

首版采用手工填写计划日期、通过表单编辑的方式。主入口位于“目标任务”，用户选择目标后，可在“任务树 / 目标地图 / 甘特图”之间切换。

首版包含：

- 单个目标的阶段与任务时间轴。
- 阶段折叠、展开及任务详情编辑。
- 计划开始、结束日期，以及未排期状态。
- 现有前置依赖的展示和日期冲突提示。
- 当前任务状态及今日标记。
- 月份切换和手机横向浏览。

后续范围包括：跨目标汇总、拖拽调整日期、自动推算工期、自动顺延、甘特日期与每日排期联动、完成百分比、计划与实际周期对照。首版不实现这些能力。

## 阶段与任务

现有 `milestone` 类型默认按“阶段”理解，在甘特图中显示为阶段条。阶段即使尚无子任务，也可以设置一段计划周期。

示例：

```text
论文研究
├─ 文献调研阶段
│  ├─ 检索与筛选文献
│  └─ 整理研究现状
├─ 实验验证阶段
│  ├─ 准备数据
│  └─ 完成对比实验
└─ 论文撰写阶段
```

阶段可折叠、展开，子任务分别显示自己的时间条。阶段和任务继续使用已有层级、类型、状态及完成操作；日期汇总本身不触发状态变更。

## 日期规则

### 手填计划日期

- 阶段允许先设置开始、结束日期，再逐步拆分子任务。
- 普通任务也可手填开始、结束日期。
- 开始、结束日期同时填写或同时留空；结束日期不得早于开始日期。
- 日期按日表达，结束日期包含当天，允许当天开始、当天结束。
- 旧任务默认没有计划日期，显示为“未排期”。
- 创建阶段时突出日期输入，方便先搭建整体计划。
- 新建子任务时，表单展示所属阶段的日期范围作为参考，子任务日期由用户填写。

### 自动汇总

对于有子任务的父项，显示日期按以下优先级确定：

1. 父项手填了日期：使用手填范围。
2. 父项没有手填日期，但有已排期子项：从子项显示范围中取最早开始、最晚结束，并标记“自动汇总”。
3. 父项和子项均没有可用日期：显示为“未排期”。

嵌套父项按同样规则逐层汇总。自动汇总值属于展示结果，应与用户手填的日期区分；清除父项的手填日期后，恢复自动汇总。

如果仍有子任务未排期，界面需要保留未排期提示，避免把部分子任务的日期误解为全部工作已经排完。

### 日期提示

- 子任务超出手填的阶段日期时，显示提示，由用户选择调整阶段或子任务。
- 任务计划结束日期超过目标的 `target_date` 时，显示提示。
- 后续任务计划开始日期早于前置任务计划结束日期时，显示依赖日期提示。
- 只对具备相关日期的数据进行日期比较；提示不自动改写日期，也不阻止保存。

## 视图与交互

- 左侧沿用目标的任务树结构，名称区域保持可见；右侧绘制时间轴。
- 默认显示本月，支持前后翻月和回到今天。
- 时间条按计划日期绘制，用颜色和文字区分待开始、进行中、受阻、已完成等现有状态。
- 未排期任务保留在左侧，并提供进入编辑窗口补充日期的入口。
- 点击任务或阶段，复用任务编辑窗口，编辑后刷新甘特图及相关视图。
- 展示已有前置依赖；点击任务可查看具体前置关系。
- 手机端支持横向滚动时间轴，任务名称区域保持可见。
- 首版以任务状态表达推进情况；专注时长和今日推进记录不直接换算为任务完成百分比。

## 与现有每日排期的关系

甘特日期用于表达长期计划。每日安排继续按现有主要科研目标、任务状态、真实前置依赖、每日预算和既有承诺保护规则生成。

因此，手工修改甘特日期不会要求每日安排按该日期自动搬移、提前或延期。甘特图中的计划日期，也不代表任务已经具备实际执行资格。

现有 `depends_on` 继续表达必须取得前置成果的依赖。阶段排列和任务排列只表达顺序；前置任务是否真正完成，继续由现有执行资格规则判断。

## 实现位置与数据建议

以下是实现建议，具体字段和接口名称可在开发中调整：

- `web/src/GoalManager.tsx`：增加甘特图入口，在现有编辑表单加入计划日期；`milestone` 类型按阶段表达。
- 新增甘特图组件及样式：负责时间轴、层级折叠、依赖展示、未排期状态和日期提示。
- `web/src/types.ts`：补充任务计划日期，以及必要的展示投影类型。
- `internal/persistence/models.go`：任务补充可空的手填计划开始、结束日期；自动汇总范围由子项计算，避免与手填值混淆。
- 数据库迁移：同步仓库迁移及嵌入迁移目录，并更新迁移版本。
- 任务创建、修改、任务树和快照链路：支持计划日期的校验、读取、保存、清空及现有版本冲突处理。
- 时间轴复用同一目标的任务数据，不直接把现有七天每日安排当作任务持续时间。

助手通过对话调整甘特日期的能力属于后续范围。开发时应检查现有助手提案、快照、恢复等写入链路，确保已有操作能够保留新增日期。

## 验收场景

1. 打开任意已有目标，可以切换到甘特图；旧任务显示为未排期。
2. 创建一个阶段，先填阶段周期，再添加并排期子任务，阶段显示手填范围。
3. 阶段未填日期时，已排期子任务可以形成自动汇总范围；子任务日期变更后，汇总随之变化。
4. 清除阶段手填日期后，恢复自动汇总；没有任何可用日期时恢复未排期状态。
5. 部分子任务未排期时，界面同时展示已知范围和未排期提示。
6. 子任务超出阶段范围、任务超过目标日期、依赖日期冲突时，用户能看见提示并继续调整。
7. 折叠、展开阶段，切换月份，回到今天，以及点击编辑后刷新均可正常使用。
8. 在手机宽度下可以浏览时间轴，同时辨认任务名称。
9. 修改甘特日期后，每日安排继续遵循既有排期及执行资格规则。
10. 不合法的日期组合不能保存；发生现有版本冲突时，不覆盖他处更新。
